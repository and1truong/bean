# Goal: Generic scoped resource lists (completed)

Add a metadata-driven `resource-list` Block that renders any AdminResource inside a Page, scopes its View through immutable route bindings, and exposes only explicitly configured interactive filters.

The blog demonstrates the capability at `/blog/:id/comments`: editors can see comments for exactly one post, default the queue to `pending`, change the status filter, and run the existing moderation Actions. Core packages contain no blog/comment-specific branches.

## Acceptance criteria

- `resource-list` references an AdminResource and reuses its View, columns, labels, pagination, and Actions.
- Required parent inputs are compiled against the referenced View's exposed filters and resolved from Page context.
- Client filters are compiler-validated, explicitly allowlisted, and cannot collide with immutable bound inputs.
- Default filter values are typed and presentation-only; authorization remains in View and Action policies.
- Anonymous/member users cannot access an editor-scoped list or its moderation Actions.
- The browser scenario proves two posts cannot leak comments across scoped routes.
- No application-specific branches are added to core Go or React code.
