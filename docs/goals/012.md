# Goal: Bean v0.11 First-class Semantic Test Suites

Status: complete

Bean v0.11 added canonical `TestSuite` metadata targeting stable Rule and Action identities. Cases use typed fixtures and explicit actor, tenant, time, request, ID, and seed context; execute through the production Rule evaluator and Action service; and assert deterministic results, errors, mutations, events, and audit records.

## Completed contract

- TestSuite is registry-owned metadata with canonical schema, capabilities, inspection, references, semantic diff, stable diagnostics, and immutable `bean/appir/v4` storage.
- Rule and Action cases are isolated in fresh SQLite runtimes, bounded to five seconds, and leave no state behind.
- Fixture records are typed and relation-checked. Action reads use a runner-owned View; writes use the production Action path.
- `bean app test --json` retains release smoke checks and returns stable suite/case evidence plus safe assertion diagnostics.
- Commerce, ATS, and booking carry maintained metadata suites for calculation, Policy/guard behavior, derivation, invariant rollback, mutations, and events.
- Provider mocks, generated tests, direct Policy/Lifecycle targets, and PostgreSQL-backed suite execution remain deferred as documented.
