# v0.7 Demo Factory benchmark

This benchmark measures the complete prompt-to-package path without embedding an agent in Bean. A runner invokes an external coding agent, records its identity and budgets, and allows that agent to use only the public Bean CLI contract and repository-shipped pattern guidance.

## Run record

Every run records:

- case name and immutable prompt text
- agent, model, model version, reasoning level, and provider
- Bean commit/version, pattern catalog version, and skill/tool versions
- cold or warm state and disclosed caches
- token budget, tool-call budget, elapsed time, and validation attempts
- every Bean command and exit status
- human interventions after the initial prompt
- behavior score, presentation score, package checksum, and failure reason

A changed prompt, model, budget, tool, skill, or cache state defines a different cohort. p50 and p90 are reported only within one cohort.

## Case 1: applicant tracking system

Prompt:

```text
Build a lightweight applicant tracking system.
Candidates, jobs, interview stages, notes,
kanban pipeline, candidate detail, search.
Include a dashboard and recent activity. Make it look professional with an indigo accent and populate it with realistic demo data.
```

Behavior rubric, all required:

- jobs, candidates, notes, and activities are represented by related Entities
- candidates have an enum stage and can move only through the declared transition Action
- the root page includes at least two aggregate metrics and a recent-activity timeline
- a board groups candidates by every declared stage
- candidate detail links to related notes/activity without cross-candidate leakage
- public search is limited to compiler-declared candidate fields
- at least three jobs, twelve candidates, and twelve related activity/note rows are populated
- generated relations point to existing records and generated values pass field validation
- the package starts and the required Views return populated data

Presentation rubric, reported separately:

- application display name is specific to recruiting rather than `Bean`
- professional preset and indigo accent are visible in the shell
- dashboard, pipeline, and detail routes have meaningful empty-state and heading text
- generated names, job titles, email addresses, notes, dates, and stages are coherent and non-placeholder-like
- no required route opens as an empty CRUD surface

## Case 2: CRM

Prompt:

```text
Build a small sales CRM with companies, contacts, deals, pipeline stages, activities, search, a revenue dashboard, and realistic demo data.
```

Required behavior: related companies/contacts/deals, transition-only pipeline movement, searchable contacts and deals, aggregate deal metrics, recent activity, populated detail routes, and a portable package.

## Case 3: issue tracker

Prompt:

```text
Build a lightweight issue tracker with projects, assigned issues, comments, a kanban workflow, nested work items, search, dashboard metrics, and realistic demo data.
```

Required behavior: project-scoped issues, assignment, comments, transition-only movement, parent/child presentation, searchable declared fields, aggregate metrics, populated detail routes, and a portable package.

## Qualification target

- p50 elapsed time below five minutes
- p90 elapsed time below ten minutes
- zero human modification after the initial prompt
- 100% behavior rubric for every accepted run
- presentation score always reported and never folded into the behavior score

The initial v0.7 record is added only after the commands, reference definitions, fixtures, and package verifier exist. Prepared-definition replay is useful contract evidence but is not reported as prompt-to-demo agent performance.
