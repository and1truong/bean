# v0.6 structured repair benchmark

- Date: 2026-09-01
- Bean: `0.6.0-alpha`
- Harness: `internal/agenttest` using the compiled binary
- Gate: `make test-blackbox`

## Purpose

This is the deterministic contract benchmark for the v0.6 repair loop. It proves that a machine client can repair and publish definitions without inspecting Bean source code or parsing diagnostic messages. It is not an external-model timing run and does not claim the roadmap's five-minute North Star.

## Invalid fixture

The applicant-tracking fixture starts with three independent defects:

- View references `canddate` instead of Entity `candidate`.
- View selects field `stage` instead of enum field `status`.
- Action declares transition source `screening`, which is absent from the status enum.

## Machine-only repair

The harness performs three validation/repair iterations:

| Iteration | Code | Path | Structured repair input |
| --- | --- | --- | --- |
| 1 | `BEAN-E2001` | `spec.entity` | `candidates: [candidate]` |
| 2 | `BEAN-E2101` | `spec.fields` | candidate list containing `status` |
| 3 | `BEAN-E2201` | `spec.transitions.screening` | enum-derived state candidates |

The harness selects from structured candidates and never matches the English `message` field. After repair it runs capabilities, schema, validate, named inspect, plan, publish, zero-change diff, and isolated lifecycle test through JSON only. It asserts exit statuses, one-document stdout, empty stderr, CLI API version, and empty diagnostics on success.
