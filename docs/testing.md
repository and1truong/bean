# Testing

`make test` runs Go and React unit tests. `make test-integration` exercises SQLite release, Action concurrency, and tenant isolation. `make test-e2e` builds the embedded binary and runs sequential Chromium workflows with isolated temporary databases. Playwright keeps traces, screenshots, and video on failure.

`bean app test` retains its compile, migration, publication, and restart smoke checks and also runs every metadata `TestSuite`. Generated replay suites use explicit expectations; Policy-denial and invalid-transition cases require a provable negative; representative create/update/delete smoke suites use deterministic DemoSeed records. Generated suites use the reserved `generated_` identity prefix and pass through the same compiler, immutable AppIR, isolation, production Rule/Action paths, and bounds as explicit suites. The generator never evaluates the implementation to invent an expected business result.

Each suite case gets a fresh ephemeral SQLite database, explicit fixtures and actor/tenant/time/ID/seed context, and the production Rule evaluator or Action service. A `changes` assertion proves that at least one named value differs from the before snapshot; `absent: true` instead asserts a hard delete. Machine output reports stable ordered suite/case status; assertion failures use `BEAN-T1001` with safe expected/actual digests. Structural schema, Rule-bound, Policy, Lifecycle, and route checks carry stable Definition identities and evidence; eligible anonymous static Pages and View display routes are exercised through the restarted production HTTP handler. Semantic-suite execution is bounded to 64 suites, 128 cases per suite, 1,024 fixtures per case, 1 MiB of encoded suite data, and five seconds per case.

An Action case that reaches an `extension` step declares ordered typed results under `providers.<extension>` and may assert ordered `expect.providerCalls`. The isolated runner executes the production enqueue and after-commit delivery paths with that mock and never opens the network. Calls expose the Extension name, invocation ID, identical idempotency key, and typed input. Missing or exhausted mocks, unexpected calls, invalid output, and unconsumed results fail with redacted `BEAN-T1001` evidence.

`make test-blackbox` builds the real binary and runs the v0.6 JSON-only structured repair/publication benchmark plus human-output compatibility checks for every agent command. Agent Protocol tests cover all ten shared handlers, exact CLI/MCP structured-result parity including generated evidence, authorization for each plane in each transport, current and legacy MCP framing, malformed requests, EOF, stdout cleanliness, and View/Action owner/tenant boundaries. Rule contracts cover every source/operator/bound, compiler diagnostics, Policy-before-guard ordering, simultaneous derives, client override refusal, candidate invariants, rollback, replay, DemoSeed, AppIR compatibility, and restart. Generated-test contracts cover deterministic materialization, reserved identities, explicit-oracle replay, Policy and Lifecycle negative mutation detection, DemoSeed relation-complete CRUD, stable structural evidence, HTTP journeys, and byte-identical repeated machine results. `make test-postgres` repeats the Application Plane, Lifecycle transition, and booking Rule derive/invariant paths on PostgreSQL 17; semantic suites intentionally execute only on isolated SQLite.

Explore contracts cover candidate-View preview parity, View-owned search, typed grouping/aggregate validation, UTC date buckets, null/order behavior, group overflow, result-shape/display compatibility, page-filter target mapping, immutable context separation, typed drill bindings, and selected Action references. CRM uses explicit multi-actor fixtures to prove authorization predicates run before aggregation and that drill IDs equal aggregate contributors. Commerce's batch integration test proves ordered non-atomic partial success while reusing ordinary Action checks. Five agent prompt fixtures inspect semantic artifacts and verify deterministic recompilation rather than matching a generated YAML string.

The ATS browser journey also measures cold and warm existing-Entity onboarding through preview, save, validation/semantic changes, publish, and the generated page route. The recorded local evidence is in [`docs/benchmarks/v0.15-explore.md`](benchmarks/v0.15-explore.md); it deliberately excludes pre-authored definitions from the generated artifacts and does not substitute automation latency for an external-agent p50/p90 claim.

`make check` adds formatting, vet, lint, TypeScript, race detection, frontend build, the black-box agent contract, and every browser suite. `asana.spec.ts` covers split-source project context plus board/tree/file behavior; `ats.spec.ts` covers the recruiting overview, filters, drill, Explore save, Lifecycle movement, and populated data; `booking.spec.ts` covers calendar and interval Rules; `crm.spec.ts` covers actor-scoped operations; `commerce.spec.ts` covers observe-to-act order transitions; `tracker.spec.ts` covers fixed small/medium/large Panel presets, source-order and overflow containment, plus status chart-to-record drill. `package.spec.ts` starts the copied executable after deleting its source. `make build` produces `bin/bean`.
