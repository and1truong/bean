# Security

Passwords use bcrypt and raw values never enter AppIR, logs, audit rows, Action output, or idempotency results. Local registration is application-opt-in, assigns a compiler-validated literal role, and has a bounded in-memory throttle independent from login. Rate limiting uses the direct peer address by default; deployments behind reverse proxies may configure their proxy IPs or CIDRs with `bean serve --trusted-proxy`, and `X-Forwarded-For` is honored only for requests from those peers. The chain is read from the trusted edge inward, so attacker-supplied prefixes cannot replace the nearest untrusted client address. Sessions are database-backed HttpOnly SameSite=Lax cookies with configurable Secure mode; authenticated Action, Webform, and cookie mutations require a per-session CSRF header. Request bodies are capped at 1 MiB.

Policy checks and Page/Block bindings are server-side. Bound View, Webform, and resource-list values are recomputed from the matched route and client collisions are rejected. A resource-list is compiler-restricted to editor/administrator readers and accepts only compiler-validated interactive filters declared by its metadata; bound scope fields cannot be exposed as interactive filters. Editor audit reads require an entity/id pair and first authorize that record through its AdminResource View; only administrators may read unscoped or system audit history. Tenant/owner constraints become DBAL predicates, field redaction occurs before rendering, write access defaults to deny, and administrator access is explicit. Queries parameterize values and validate identifiers. Filtered content is rendered server-side and passed through a strict HTML allowlist before it can be marked as formatted in the UI. Markdown raw HTML, executable elements, images, event attributes, and unsafe URL schemes remain inert. Legacy rich text is trusted by Page rendering only when the underlying Entity field has the `richtext` type; unfiltered persisted values are re-sanitized on every View read so pre-upgrade rows remain safe. View results cap at 200. Uniform errors include a request ID and omit database details.
