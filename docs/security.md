# Security

Passwords use bcrypt and raw values never enter AppIR, logs, audit rows, Action output, or idempotency results. Local registration is application-opt-in, assigns a compiler-validated literal role, and has a throttle independent from login. Sessions are database-backed HttpOnly SameSite=Lax cookies with configurable Secure mode; authenticated Action, Webform, and cookie mutations require a per-session CSRF header. Request bodies are capped at 1 MiB.

Policy checks and Page/Block bindings are server-side. Bound View, Webform, and resource-list values are recomputed from the matched route and client collisions are rejected. A resource-list accepts only compiler-validated interactive filters declared by its metadata; bound scope fields cannot be exposed as interactive filters. Tenant/owner constraints become DBAL predicates, field redaction occurs before rendering, write access defaults to deny, and administrator access is explicit. Queries parameterize values and validate identifiers. Filtered content is rendered server-side and passed through a strict HTML allowlist before it can be marked as formatted in the UI. Markdown raw HTML, executable elements, images, event attributes, and unsafe URL schemes remain inert. Legacy rich text is trusted by Page rendering only when the underlying Entity field has the write-sanitized `richtext` type. View results cap at 200. Uniform errors include a request ID and omit database details.
