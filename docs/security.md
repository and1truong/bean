# Security

Passwords use bcrypt and raw values never enter AppIR, logs, audit rows, Action output, or idempotency results. Local registration is application-opt-in, assigns a compiler-validated literal role, and has a throttle independent from login. Sessions are database-backed HttpOnly SameSite=Lax cookies with configurable Secure mode; authenticated Action, Webform, and cookie mutations require a per-session CSRF header. Request bodies are capped at 1 MiB.

Policy checks and Page/Block bindings are server-side. Bound View, Webform, and resource-list values are recomputed from the matched route and client collisions are rejected. A resource-list accepts only compiler-validated interactive filters declared by its metadata; bound scope fields cannot be exposed as interactive filters. Tenant/owner constraints become DBAL predicates, field redaction occurs before rendering, write access defaults to deny, and administrator access is explicit. Queries parameterize values and validate identifiers. Rich text preserves a small formatting allowlist while scripts, attributes, and unsafe URL schemes remain inert. View results cap at 200. Uniform errors include a request ID and omit database details.
