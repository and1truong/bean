# Security

Passwords use bcrypt and raw values never enter AppIR, logs, audit rows, Action output, or idempotency records; registration ignores generic idempotency keys so no fast password fingerprint is persisted. Local registration is application-opt-in, assigns a compiler-validated literal role, and has a bounded in-memory throttle independent from login. Rate limiting uses the direct peer address by default; deployments behind reverse proxies may configure their proxy IPs or CIDRs with `bean serve --trusted-proxy`, and `X-Forwarded-For` is honored only for requests from those peers. The chain is read from the trusted edge inward, so attacker-supplied prefixes cannot replace the nearest untrusted client address. Sessions are database-backed HttpOnly SameSite=Lax cookies with configurable Secure mode; authenticated Action, Webform, and cookie mutations require a per-session CSRF header. Request bodies are capped at 1 MiB.

Policy checks and Page/Block bindings are server-side; bound View and Webform requests recheck the enclosing Page, Panel, and Block policies. Bound View, Webform, and resource-list values are recomputed from the matched route and client collisions are rejected. A resource-list is compiler-restricted to editor/administrator readers and accepts only compiler-validated interactive filters declared by its metadata; bound scope fields cannot be exposed as interactive filters. Editor audit reads require an entity/id pair and first authorize that record through its AdminResource View; only administrators may read unscoped or system audit history. Tenant/owner constraints become DBAL predicates, field redaction occurs before rendering, write access defaults to deny, and administrator access is explicit. Queries parameterize values and validate identifiers. Filtered content is rendered server-side and passed through a strict HTML allowlist before it can be marked as formatted in the UI. Markdown raw HTML, executable elements, images, event attributes, and unsafe URL schemes remain inert. Legacy rich text is trusted by Page rendering only when the underlying Entity field has the `richtext` type; unfiltered persisted values are re-sanitized on every View read so pre-upgrade rows remain safe. View results cap at 200. Uniform errors include a request ID and omit database details.

Agent Protocol plane grants and runtime identity are process configuration. Plane denial occurs before parsing source or opening a target; MCP discovery omits unauthorized tools. Tool input cannot set roles, tenant identity, grants, raw tables, arbitrary mutations, or SQL. Application reads resolve a compiled View and writes resolve a compiled Action, then run the same Policy, owner, tenant, validation, transaction, audit, job, outbox, and idempotency logic used by HTTP. Lifecycle state is initialized and changed only inside that Action boundary; generic updates and transaction update steps cannot bypass its graph. Rule guards run after Policy and can only further deny; derived inputs are server-owned; Entity invariants run before persistence. Rule evaluation has no network, filesystem, SQL, environment, process, module, random, implicit clock, or mutation source and enforces fixed node/depth/literal/value bounds. Explicit and generated TestSuite definitions execute only inside bounded, disposable local SQLite state with explicit context; generated cases retain explicit expectations or derive only negative semantics Bean can prove, and Rule/Action targets still use production Policy paths. Runtime errors redact database URL passwords and connection password options; Rule inspection hashes redacted literals so semantic changes remain visible without revealing values. The v0.12 MCP surface is local stdio; it does not accept remote credentials or expose a network listener.
