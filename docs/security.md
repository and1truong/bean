# Security

Account password changes and all-session revocation use built-in transactional Actions, require session/CSRF validation, and throttle separately from login. Host-only stdin password recovery is audited and never exposed over HTTP. Session creation uses a user-row compare-and-swap lock so a concurrent reset cannot mint a session using stale credentials. No password input or fingerprint is stored in Action idempotency records.

Application authentication choices are documented in [Authentication configuration](authentication.md). Explicit presets keep self-registration off unless enabled; the shared Action boundary enforces the opt-in for HTTP and non-HTTP callers alike.

Passwords use bcrypt and raw values never enter AppIR, logs, audit rows, Action output, or idempotency records; registration ignores generic idempotency keys so no fast password fingerprint is persisted. Local registration is application-opt-in, assigns a compiler-validated literal role, and has a bounded in-memory throttle independent from login. Rate limiting uses the direct peer address by default; deployments behind reverse proxies may configure their proxy IPs or CIDRs with `bean serve --trusted-proxy`, and `X-Forwarded-For` is honored only for requests from those peers. The chain is read from the trusted edge inward, so attacker-supplied prefixes cannot replace the nearest untrusted client address. Sessions are database-backed HttpOnly SameSite=Lax cookies with configurable Secure mode; authenticated Action, Webform, and cookie mutations require a per-session CSRF header. Request bodies are capped at 1 MiB.

Policy checks and Page/Block bindings are server-side; bound View and Webform requests recheck the enclosing Page, Panel, and Block policies. Bound View, Webform, and resource-list values are recomputed from the matched route and client collisions are rejected. A resource-list is compiler-restricted to editor/administrator readers and accepts only compiler-validated interactive filters declared by its metadata; bound scope fields cannot be exposed as interactive filters. Editor audit reads require an entity/id pair and first authorize that record through its AdminResource View; only administrators may read unscoped or system audit history. Tenant/owner constraints become DBAL predicates, field redaction occurs before rendering, write access defaults to deny, and administrator access is explicit. Queries parameterize values and validate identifiers. Filtered content is rendered server-side and passed through a strict HTML allowlist before it can be marked as formatted in the UI. Markdown raw HTML, executable elements, images, event attributes, and unsafe URL schemes remain inert. Legacy rich text is trusted by Page rendering only when the underlying Entity field has the `richtext` type; unfiltered persisted values are re-sanitized on every View read so pre-upgrade rows remain safe. View results cap at 200. Uniform errors include a request ID and omit database details.

Explore preview is administrator-only and can submit only a bounded candidate View specification against Entities already present in the active AppIR. It cannot select a table, SQL, Policy, actor, tenant, provider, or hidden field. Preview and saved Views execute through the same compiler and `view.Service`. For grouped and metric results, actor/tenant/owner/Policy predicates and fixed filters are placed in the database query before grouping or aggregation. Hidden rows therefore cannot affect counts, sums, group categories, empty states, or drill contribution sets. A drill carries only compiler-approved group/filter bindings and re-runs the target View under its own Policy; its derived route is navigation, never query authority.

Page filters target an explicit Block and exposed filter, are type-checked at compilation, and cannot collide with trusted route/context bindings. Public record batches accept at most 200 unique IDs and cannot override the record ID through shared values. They execute the existing Action service sequentially, so authorization, Rule guards, Lifecycle transitions, optimistic concurrency, transactions, audit, and idempotency are checked independently for every record. Partial success is reported; bulk execution is not an atomic authorization shortcut.

Agent Protocol plane grants and runtime identity are process configuration. Plane denial occurs before parsing source or opening a target; MCP discovery omits unauthorized tools. Tool input cannot set roles, tenant identity, grants, raw tables, arbitrary mutations, or SQL. Application reads resolve a compiled View and writes resolve a compiled Action, then run the same Policy, owner, tenant, validation, transaction, audit, job, outbox, and idempotency logic used by HTTP. Lifecycle state is initialized and changed only inside that Action boundary; generic updates and transaction update steps cannot bypass its graph. Rule guards run after Policy and can only further deny; derived inputs are server-owned; Entity invariants run before persistence. Rule evaluation has no network, filesystem, SQL, environment, process, module, random, implicit clock, or mutation source and enforces fixed node/depth/literal/value bounds. Explicit and generated TestSuite definitions execute only inside bounded, disposable local SQLite state with explicit context; provider calls use typed offline mocks and their values are redacted from inspection and failure evidence.

Extensions are the only application-declared external execution boundary. They cannot read Bean storage and run only from a committed Action outbox intent. Endpoints, typed fields, permissions, effects, authentication mode, timeout, and fixed retry bounds are compiler validated; redirects are refused and response bodies are bounded and never persisted as errors. Bearer tokens come only from the host's `BEAN_EXTENSION_BEARER_TOKENS` JSON configuration and never enter definitions, AppIR, logs, audit, outbox payloads, inspection, or tests. Delivery is at-least-once and reuses one immutable idempotency key; it does not claim exactly-once provider effects. Runtime errors also redact database URL passwords and connection password options; Rule inspection hashes redacted literals so semantic changes remain visible without revealing values. View display bindings are recomputed from matched route/context values, reject client collisions, and preserve the View Policy/redaction path. The v0.15 MCP surface is local stdio; it does not accept remote credentials or expose a network listener.
