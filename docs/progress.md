## Visual agentic browser testing

Status: in progress (slice 9 of 14). Contract: [`GOAL.md`](../GOAL.md). Epic: <https://github.com/and1truong/bean/issues/20> — sub-issues #23–#36 ship as PRs into `epic/browser-testing`, which merges to main as one umbrella PR at the end.

- Slice 1 (ticket #23) added the `Scenario` definition kind: `internal/scenario` publishes the closed node-type, condition, assertion, and bound contract; the compiler validates source shape per node type, required fields, edge integrity (dangling `next`/`onFail`/`body`/`branches[].next` targets and unreachable nodes are `BEAN-E2891` diagnostics, never panics), and `api_call` Action references, then compiles into immutable `App.Scenarios` on AppIR v21 (`ScenarioFormat`).
- `fill` accepts `text` XOR `secret` (secret resolves at execution time, outside AppIR); `pause` reserves the takeover seam for slice 10.
- Generated `schemas/scenario.schema.json` via `go run ./cmd/bean schema --output schemas --json`; capabilities publish node types, conditions, assertions, and bounds. Format gate: scenarios require v21 exactly; pre-v21 snapshots reject them.
- Verification: `go test ./internal/compiler ./internal/appir ./cmd/bean` passes, including the v21 format compatibility matrix and canonical-schema drift checks.
- Slice 2 (ticket #24) added the durable run model in `internal/scenariorun`: `Run → Session → StepExecution → Artifact/Event` rows on five `bean_run*` metadata tables, lifecycle `pending → running → paused → completed|failed|cancelled`, token claims with lease-based `RecoverStale` that deterministically fails expired claims (browser sessions cannot survive restart) while paused/pending runs stay resumable, step retries as `UNIQUE(run_id, node_id, attempt)` rows, and append-only events with per-run monotonic sequences — no transaction spans a run.
- Slice 3 (ticket #25) added `internal/browserapi`, the Semantic Browser API contract: `Session` interface (open/snapshot/click/fill/select/press/wait/extract/screenshot/close), normalized `Snapshot` with deterministic canonical encoding (`[ref=e12] button "Continue"`), snapshot-scoped `Ref` serialization (`<snapshot>:e<n>`) with `ErrStaleRef`/`ErrUnknownRef` invalidation semantics, and the closed bounded wait-condition vocabulary mirroring the scenario node kinds. No adapter types cross the boundary; the Playwright implementation is slice 4.
- Slice 4 (ticket #26) implemented the Semantic Browser API over Playwright: `browser/sidecar.mjs` is a Bean-controlled child process speaking newline JSON RPC over stdio (one process = one browser context = one session), `internal/browserplaywright` implements `browserapi.Session` over it with spawn/health-check/shutdown/crash-to-dead-session lifecycle, and `internal/scenarioexec` executes a compiled scenario end to end — claim, session, per-node `StepExecution` rows, failure-screenshot artifacts, pause semantics — driving real Chromium in tests.
- Slice 5 (ticket #27) made runs observable end to end: the sidecar streams page observations (console, page errors, request/response/request-failed) as unsolicited event frames and records a Playwright trace per session; `browserapi.Session` gained `Events()` and `Trace()`; `internal/scenarioexec` pipes session events plus snapshot, assertion, and artifact evidence into the durable log and persists the failure diagnosis bundle (screenshot + DOM snapshot + trace zip) as artifact files under `Executor.ArtifactDir`; and `GET /api/scenario-runs/{id}/events` serves the log as JSON or a resumable `text/event-stream` (Last-Event-ID / `?after=` sequence offsets).
- Slice 6 (ticket #28) exposed the scenario and run surface over `internal/httpapi` and added the in-process `internal/scenariorunner`: `GET /api/scenarios` lists compiled scenarios (authoring stays on `/api/admin/definitions`), `POST /api/scenario-runs` enqueues + wakes the runner, `GET /api/scenario-runs[/{id}]` lists and details runs with sessions/steps/artifacts, `POST /api/scenario-runs/{id}/pause|resume|stop` drives run control (cooperative pause between nodes via `Executor.PauseRequested`, context-cancel for in-flight stop, `Store.Cancel` for unclaimed pending/paused), and `GET .../artifacts/{id}` downloads evidence files with a path-traversal guard. The runner ticks alongside the job runner in serve; reads are editor-scoped and mutations require editor + CSRF — scenario execution does not inherit Action trust.
- Slice 10 (ticket #32) turned pause into interactive takeover: a paused run parks its live walker in `scenarioexec.Held` (session, event pump, resolved secrets stay alive), `POST /api/scenario-runs/{id}/manual` drives human ops on the parked browser — each recorded as a `manual_action` event (never a StepExecution row), and a `resume_point` event durably records the boundary node the walk resumes from. Resume reclaims the run and continues on the held session at that boundary; when the held session is gone (process restart) the walk still continues at the boundary on a fresh session — steps never re-run, so assertions evaluate the state the human left. Stopping a parked run closes its held session; Studio's paused run view gains a takeover card (op picker + args + result/screenshot) feeding the same event log, which is the recorded input #34 replays.
- Slice 11 (ticket #33) added NL → scenario generation behind `POST /api/scenario-generate` (editor + CSRF): `internal/scenariogen` defines a provider-neutral `Generator` with an Anthropic Messages-API implementation wired from `BEAN_ANTHROPIC_API_KEY`/`BEAN_ANTHROPIC_MODEL`/`BEAN_ANTHROPIC_ENDPOINT` (unconfigured → 503). `Draft` loops generate → `compiler.CompileScenarioCandidate` (a new seam mirroring `CompileViewCandidate`, compiling the draft against the active app so api_call/action references validate) → diagnostic feedback back into the next attempt, bounded at 3 attempts; uncompilable output returns 422 with diagnostics and is never saved. The system prompt's node vocabulary is generated from the same `internal/scenario` tables the compiler enforces (new `scenario.Fields` accessor), so generation is constrained to compiler-accepted node types by construction. A successful draft returns `{name, spec}` with `Agent-generated from prompt …` provenance stamped into `spec.description`; Studio's Scenario editor gained a "Generate from description" card that fills the editable spec + name — the user reviews and saves through the normal definition flow.
- Slice 12 (ticket #34) turned run traces into scenario drafts: `POST /api/scenario-runs/{id}/save-as-test` (editor + CSRF) runs `internal/scenariotrace.Spec`, which merges passed/failed StepExecutions (cloned back to primitive nodes — branch/loop/pause control nodes and skipped steps drop out) with `manual_action` events (mutating ops rebuild as nodes labeled `manual <op>`; observational snapshot/screenshot/extract ops and failed ops drop out) into one chronological graph ordered by `CreatedAt`, dedups consecutive identical nodes, and re-ids it `step_1..n` with linear `next` edges — element refs carry the semantic element *name* recorded at action time (`manual_op` payloads now include the snapshot's element name plus all op args) since snapshot-scoped refs go stale. Like scenario-generate the draft is returned `{name, spec}`, never saved; Studio's run detail gained a "Save as test" button that loads it into the Scenario editor for review and explicit save, producing a scenario that re-runs the same workflow.
- Slice 7 (ticket #29) drew the browser-run security boundary as host configuration (`scenarioexec.Policy`): `BEAN_BROWSER_ALLOWED_DOMAINS` refuses non-listed navigation with a `policy_blocked` event and the sidecar context route aborts matching egress (`request_blocked`), `BEAN_BROWSER_MAX_DURATION` bounds wall time (ctx-cancelled failures now finish `cancelled` on a detached context, fixing a stuck-running run when stop landed mid-setup), `BEAN_BROWSER_PAUSE_ON` gates node types behind durable `policy_pause` approvals, and secret fills audit `secret_used` while resolved values are scrubbed from event payloads, snapshots, and artifacts before persistence.
- Slice 8 (ticket #30) added the Studio live run view: `/studio/runs` lists runs with a status filter and starts a run by scenario, and `/studio/runs/:id` renders three columns — the compiled node graph with the executing node highlighted, the step timeline (status/attempt/duration, click to select), and a diagnostics card that defaults to the failing step and shows its error/output, inline screenshot artifact, and step-scoped console/network/assertion events. Live updates ride the reconnectable `EventSource` stream on `/api/scenario-runs/{id}/events` into react-query invalidation; pause/resume/stop controls post to the run endpoints from the header.
- Slice 9 (ticket #31) added the Studio scenario graph editor: `Scenario` joins the visual definition editors — a node palette creates any of the 13 node types, each node card edits type-specific required/optional fields (conditions driving conditional ref/text inputs, branch edge lists with add/remove, loop until/body/maxIterations, api_call Action reference + JSON input, script bodies), edge selects wire `next`/`onFail`/branch targets/loop `body`/`start`, and id renames or node removals rewrite every referencing edge. Save goes through the ordinary definition draft flow so compiler diagnostics (dangling edges, unreachable nodes, bad fields) surface in Studio.
- Slice 13 (ticket #35) added agent-assisted repair on top of the failure diagnosis bundle (screenshot + DOM + trace artifacts from slice 5): `POST /api/scenario-runs/{id}/repair` (editor + CSRF, failed runs only) hands the authored Scenario spec plus a bounded failure summary (run error, failing steps' node/error/output) to `scenariogen.Repair` — the same generate → compile-check → feedback loop as NL generation — and returns `{name, spec, diff}` where `scenariogen.DiffSpecs` produces the node-level graph diff (added/removed nodes, per-node changed fields). The draft is never applied silently: Studio's failed-run view gained a "Propose repair" button rendering the diff card with a "Review in editor" action that loads the spec into the Scenario editor, where the human inspects and explicitly saves through the normal definition flow.
- Slice 14 (ticket #36) added app-driven test generation: `GET /api/scenario-proposals` (editor read) runs `internal/scenariopropose`, which walks the compiled route surface and drafts a scenario per navigable page — `happy_path` for unprotected pages (navigate, assert url_contains the route, assert the page title renders) and `auth_check` for policy-gated pages (navigate unauthenticated, assert the `/login` redirect) — skipping parameterized routes and names already taken by saved scenarios. Every proposal is compile-checked via `CompileScenarioCandidate` against the active app (the release the draft will publish into) and returned `{name, kind, title, summary, spec, valid, diagnostics}`, never saved; Studio's Scenario editor gained a 'Suggested scenarios' card listing the batch — 'Use draft' loads it into the editor for review/save, 'Dismiss' drops it client-side.

- Dogfood follow-up (PR #45 feedback): the run report counts only executed checks — the headline denominator is assertions that actually ran, so a branch's skipped edge reads `2/2 assertions passed`, not `2/3`; the executor records the chosen edge on the branch step's output (`{"target":"verify"}`) and unexecuted nodes render `skipped — branch choose took verify` (attributed via reachability over the untaken edges) or plain `skipped` on completed runs, `not run` only when the run itself didn't finish. The detail panel is `Step details` unless the selected step failed (then `Diagnostics`), and a `fill` node's literal value never renders — the row says `with a value` (`with a secret` when bound), steering authored tests toward `secret` bindings.
- Dogfood follow-up (PR #45 feedback): interaction refs resolve against compatible actionable roles — a click on "Sign in" lands on the submit button, not the heading or landmark sharing its accessible name; ambiguous or non-actionable matches (and disabled targets) fail the step loudly with candidate details instead of silently clicking the wrong ancestor. Assertion outcomes are durable: a wait timeout records an `assertion_result` event (expected vs observed, written on a detached context) and the step error states what was expected and the timeout rather than a bare "context deadline exceeded". In the event explorer, response statuses and page console output are neutral observation — only transport failures, uncaught page errors, failed assertions, and policy blocks read as problems, so an expected 401 keeps a passing test visually green.
- Dogfood follow-up (PR #45 feedback): the run detail page now reads as a test report — the header leads with the outcome (`3/3 checks passed`, duration, tested route, scenario title), the merged "Check outcome" list describes each node's user-facing action/assertion (`Go to /x`, `"ok" appears on the page`) with its result and folds never-executed nodes in as `not run`, and low-level event JSON/network noise sits behind collapsed "Technical details" (step events too). Environment failures are classified: a missing browser binary renders one "Environment setup required" card with `cd browser && bunx playwright install chromium` instead of the raw launcher exception twice, and "Save as test" hides when no step ran while a "Retry run" affordance re-enqueues the scenario. A zero-timestamp `FinishedAt` no longer renders huge negative durations on in-flight steps. `make bootstrap` installs Playwright Chromium for both `browser/` and `e2e/`, the README documents the runtime prerequisite, and vitest stubs `localStorage` when Node ≥25's experimental webstorage global shadows jsdom's.

## Configurable authentication

Status: complete for the current scope. Milestones 1–4 (account security, email recovery and verification) are complete. The user deferred onboarding/invitations; no further auth implementation is scheduled.

- Login now has duplicate-submit protection, pending/error behavior, password-manager hints, and an accessible password visibility control.
- Optional `Authentication` metadata compiles into immutable AppIR v16. Registration defaults off for explicit `local`, `internal`, and `public` presets, while omitted configuration preserves legacy behavior. Disabled registration is blocked across UI, HTTP, Webform, direct Action execution, and OpenAPI.
- Signed-in users can change their password or revoke all sessions from the Account page. Trusted host operators have an email-independent password-reset CLI. Account mutations preserve transactional audit/session behavior and pass SQLite and PostgreSQL coverage.
- Opt-in `passwordRecovery` compiles into AppIR v17; enabled publication/startup requires host mail configuration. Known and unknown valid addresses use the same encrypted durable request path and generic response. A committed worker issues 15-minute tokens, stores only digests, and queues AES-GCM-encrypted SMTP delivery. STARTTLS and certificate verification are mandatory. The browser strips fragment credentials and redeems only on explicit POST; password replacement consumes tokens and revokes sessions atomically. Release replacement/disable cancels older intents and links. Retry safety retains consumed receipts; automatic retention cleanup is not yet implemented.
- Opt-in `emailVerification` uses AppIR v19, preserving v18 field layouts and all earlier feature boundaries. Existing/new accounts start unverified; enabling blocks unverified login and session use, including built-in Account Actions. Registration queues verification atomically; generic resend handles existing accounts without exposing their status. Confirmation requires purpose-bound token plus current password, records verification, consumes tokens, revokes sessions and audits atomically. Disabling returns to email-independent login; recovery does not implicitly verify ownership.
- Latest qualification: `make check` passes 108 frontend tests, 27 browser journeys and Go/race/contracts; `make build` passes. `make test-postgres` passes recovery/verification/account HTTP parity and the Blog journey. Verification tests cover current/wrong password, expiry/purpose/release separation, concurrent consumption, audit/enqueue rollback, old sessions, disabled APIs/direct Actions/outbox and real local STARTTLS for existing and newly registered accounts. The PostgreSQL fixture uses a separate application ID to avoid deleting unrelated test Entities.
- Deferred: onboarding/invitations (milestone 5), at the user's request. OIDC/MFA remain outside scope. Unsupported switches continue to fail compilation rather than acting as inert flags. This scope closure changes documentation only; the qualification above applies to the unchanged runtime.

Runtime and security details: [`docs/authentication.md`](authentication.md).
